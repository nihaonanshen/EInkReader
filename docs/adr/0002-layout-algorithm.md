# 文本布局算法选择

## Context

阅读页面需要对文本进行精确的分页和坐标计算，以便在墨水屏上准确渲染。需要考虑的因素包括：CJK 与 ASCII 字符宽度差异、段落缩进、行间距、分页逻辑等。

## Decision

采用 **逐字符估算宽度 + 分段换行 + 按高度分页** 的算法：

1. 将文本按 `\n` 分割为段落
2. 对每个段落，逐个字符估算宽度（CJK = 1.0em，ASCII = 0.5em，零宽字符 = 0）
3. 根据最大行宽动态换行，生成带精确坐标（x, y, width, height）的行列表
4. 按页面高度将行分组为页，计算每页的内容字符串和行指标
5. 输出 LayoutResult 包含所有页的 PageData（含内容、行数和精确坐标）

该算法在 `layout_text()` 中实现，不使用任何外部文本度量库，仅基于字符类别估算宽度，确保在无字体加载情况下也能工作，同时保持接近真实排版的精度。

## Considered Options

- **使用 Android Paint.measureText()**：通过 Java 端 Paint 对象测量实际文字宽度。但每次测量都需要 JNI 调用，且需要加载字体对象，性能较差，不适合批量排版。
- **使用 HarfBuzz / ICU 等专业文本布局库**：功能强大，但体积庞大，JNI 桥接复杂，不适合轻量级阅读器场景。
- **简单的空格分割 + 固定字宽估算**：实现简单但对中文支持差，无法正确处理连排和换行。

最终选择估算方案作为折中：纯 Rust 实现、无外部依赖、速度足够（千字文本排版 < 1ms）、对 CJK/ASCII 混合文本有合理精度。

## Consequences

- ✅ 无需加载任何字体文件即可工作（字体信息从 Kotlin 传入像素尺寸）
- ✅ 完全可控，可加入首行缩进、段距等特殊格式
- ✅ 易于单元测试和基准测试
- ⚠️ 字符宽度为估算值，与真实字体渲染有轻微偏差（但对阅读体验影响极小）
- ✅ 输出精确到每个行的坐标，可直接用于 Canvas 绘制，无需二次计算
